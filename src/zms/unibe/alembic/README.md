# Generic single-database configuration

## Usage

- Create a new migration script:
  - `$ alembic revision --autogenerate -m <message>`

- Adjust the generated migration script as needed:
  - `# ### commands auto generated by Alembic - please adjust! ###`

- Apply the migration to the database:
  - `$ alembic upgrade head`

## Important notes on `alembic` migrations

- Renaming columns:
  - Alembic recognizes renaming a column (e.g., from name to first_name) by default as two separate actions. Dropping the column and adding a new column. This will result in the loss of all existing data!
  - Solution: Generate the migration, open the file manually, and replace the `drop_column` and `add_column` with the command: `op.alter_column('table_name', 'old_column_name', new_column_name='new_column_name')`.

- Adding non-nullable columns (`NOT NULL`) afterwards: 
  - If you add a column without `nullable=True` (i.e., a required column) to a table that already has data, PostgreSQL will abort the migration with an error because existing rows do not have a value for this column.
  - Solution: First create the field as `nullable=True` with a default value (default="Unknown"), populate the old data, and then set the column to `nullable=False` via a migration script.
